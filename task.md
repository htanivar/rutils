Your task is to analyze the provided input (codebase / feature list / API / system description) and produce BOTH:

1. High-Level Documentation (for stakeholders, product teams, and end users)
2. Low-Level Documentation (for internal developers and engineers)

---

INPUT:
[Paste code, feature description, API spec, or system overview here]

---

OUTPUT REQUIREMENTS:

## 1. High-Level Documentation
- Overview of the system/product
- Key features and capabilities
- User-facing workflows (step-by-step)
- Business value and use cases

- Non-technical language

## 2. Low-Level Documentation
- Architecture overview (components, services, interactions)
- Detailed module/function descriptions
- Data flow and dependencies
- API endpoints (request/response format)

- Edge cases and constraints
- Written for engineers

## 3. Internal Team Notes
- Design decisions and trade-offs
- Known limitations
- Future improvements
- Deployment considerations

## 4. User Documentation
- How to use each feature
- Step-by-step guides
- Examples
- FAQs / troubleshooting

---

FORMAT:
- Use clear headings
- Use bullet points where helpful
- Keep sections well separated
- Avoid repetition
- Be precise and structured
